# Bubble 评测说明

本文汇总 Bubble 在记忆更新、跨会话使用和 MCP 执行控制方面的测试方法与结果。

## 测试方法

测试分三层，从局部到端到端：

1. 纯函数单测：不连数据库，直接喂文本，断言输出结构（兴趣、情绪、洞察、提示词、MCP 工具分级）。
2. 脚本化模型 + 真实数据库：固定模型输出与向量，测代码逻辑（记忆更新、MCP 订单/审批）。
3. 记忆端到端：调用 `ChatService.prepare` 并消费完整 SSE 流，经过实际对话编排链路；主对话不直接调用记忆写入工具。

记忆端到端的判分用两个口径：一是新开会话追问"当前值"，二是直接查数据库最终状态
（谁 active、谁被标记 superseded、版本指针指向哪里）。每条样本用独立临时用户，跑完删除。
误失效数单独统计，不混在成功率里。

## 数据与场景

自建 JSONL 数据集，每行含预置旧记忆、新说法、预期关系（替换 / 重复 / 并存）、固定追问。
分六类测试场景，开发集用于修复，固定新表达集用于复测：

| 场景类别 | 开发集 | 固定新表达集 | 例子（旧 → 新） |
| --- | --- | --- | --- |
| replace 替换 | 8 | 4 | "秋招首选上海" → "现在更倾向杭州" |
| duplicate 重复 | 4 | 4 | "常住杭州" → "常住杭州" |
| coexist 并存 | 6 | 4 | "喜欢篮球" → "也喜欢电影" |
| negation 否定 | 4 | 4 | "喜欢篮球" → "不再喜欢篮球了" |
| scope 范围 | 4 | 4 | "求职首选杭州" → "目前常住上海" |
| legacy_noise 老数据+噪声 | 4 | 4 | 老记录无新字段，混入相似噪声 |

固定新表达集最初作为留出数据，随后参与过失败分析；本文报告的是修复后复测结果，
不将其描述为未参与调试的独立测试成绩。首次运行结果保持原样。

此外还有针对 MCP 的脚本化场景（见下）。

## 结果

| 评测 | 口径 | 结果 |
| --- | --- | --- |
| 记忆开发集（30 条） | 新会话追问（含持久化、旧值处理与追问判据） | 30/30 |
| 记忆开发集（30 条） | 最终记忆状态（离线复核，含 3 条人工等价裁定） | 29/30 |
| 固定新表达集（24 条） | 任务脚本通过 | 22/24 |
| 固定新表达集（24 条） | 最终状态正确 | 23/24 |
| 固定新表达集 | 本轮误失效 | 0 |
| MCP 服务层集成测试（模拟外部客户端） | 场景 | 12/12 |
| MCP 服务层集成测试（模拟外部客户端） | 完成标准 | 5/5 |

开发集的 30/30 与 29/30 来自同一次运行及其离线状态复核，不是两次独立运行；前者包含持久化、
旧值处理和追问判据，不是仅凭答案关键词命中。

固定新表达集任务脚本未通过的两条分别涉及"骑车/骑自行车"和中文/阿拉伯数字日期，
属于字面匹配限制；其中日期已有一次人工等价裁定。原始成绩不做修改，这两条也不被描述为产品失败。
记忆状态口径下未通过的 HU-022 是实际重复记录问题（同一轮把同一件事复述成两条记录，内容未丢失），保留说明。

## MCP 服务层集成测试

12 条场景直接调用 `MCPService` 的
`compare_luckin / preview_order / create_order / cancel_order / query_order / approve_tool`，
未经过模型聊天、HTTP API、浏览器或独立 MCP 服务；模拟层替换内部连接与客户端会话。结果为
12/12 场景、5/5 完成标准，不称为 Agent 端到端成功率。

五项完成标准：

1. 价格规格可追溯至当次查询。
2. 未经确认零次执行（本次测试范围内的审批/下单入口）。
3. 重复提交至多一个本地执行者。
4. 外部结果未知时不自动重试写操作。
5. 服务层可查询订单状态并返回取消结果。

## 两个典型问题

1. 记忆去重中，仅凭高相似度复用存在误合并风险，因此增加了语义等价与新增信息校验，
   含新信息的内容必须保留。
2. MCP 查询返回自由文本或坏 JSON 时，曾一律当成"没有找到结果"（把服务故障说成没有门店）；
   现单独报格式错误，与"没有结果""服务超时"区分开。
